# 結果不明応答のローカル管理設計案

現状、`manage` 常駐コアと Gateway/Manager は別プロセスで、Manager の `unknown_responses()` は外部へ公開されていない。管理 CLI は認証後コアに接続するが、コアから Manager に認証付き照会する経路は存在しない。結果不明はプロセス内メモリにのみある。再起動すると消えるため、永続的な安全保証はない。

## 導入案

- コアが起動する Gateway 毎に専用のランダムな認証情報を生成し、既存 CLI 用認証情報とは分離する。コア・Gateway 間に loopback 限定の管理接続を設け、起動時の匿名パイプで認証情報と接続情報を渡す。引数・ログ・Worker 子プロセス環境・Discord へ渡さない。接続情報ファイルの作成・差し替えによるなりすましを避ける。
- CLI は既存の認証済み管理接続を用い、コアは接続中の実 Gateway に照会する。Gateway の再起動・接続断時は一覧の取得失敗として返す。空一覧に偽装しない。管理の read/write・接続時間・キュー長・要求サイズに上限を設ける。
- 一覧の各項目にはインスタンスID、Worker番号、操作IDと状態のみを含め、トークン、HTTP内容、Discord本文を含めない。並びは安定化し、時点と揮発性を表示する。大量の場合はページ化する。
- 照合済みとしての解除は別の明示操作とし、インスタンスID・Worker番号・操作ID・根拠を必要とする。本人・操作・対象・時刻・結果を認証済み管理者の監査ログへ記録し、本文や秘密情報を自動付与しない。監査記録に失敗した場合は解除しない。根拠の保管先はアクセス制御された領域に限定する。
- コア・Gateway 接続の認証は片方向の bearer 値だけで済ませず、双方の接続先を起動時のパイプに束縛しリプレイ防止を考える。Unix と Windows でプロセス起動・パイプ継承が異なるため、Windows では実 ACL とハンドル継承を検証するまで機能を公開しない。
- 自動解除・再送は行わない。将来の永続ジャーナル設計ではクラッシュ後の Unknown を保全し、書き込み順序とクラッシュ復旧を検証する。

## 受け入れ試験

未認証・不正な認証・期限切れ／別インスタンスの要求、部分フレーム・巨大フレーム・接続枯渇、Gateway 再起動・コア再起動・接続途絶、監査書き込み失敗、異なる Worker の同じ操作ID、解除直前の状態変化を検証する。異常時はいずれも秘密をログへ出さず fail closed。Windows ACL と Linux 所有権・権限を各実機で試験する。

### 使い方と接続

`cargo run --bin manage -- list-unknown`。既存 CLI 認証後、常駐コアが起動した Gateway の Manager に照会する。取得完了時の Unix 秒、揮発性、状態 `Unknown`、インスタンス ID とソート済み `(Worker番号, 操作ID)` を返す。本文・HTTP内容は返さない。Gateway 不在・起動未完了・切断・期限超過は失敗終了とし、空一覧に変換しない。

Gateway 起動ごとに loopback の一時ポートと二つの独立した32バイト乱数を生成し、匿名 stdin パイプへ渡して閉じる。引数は非秘密の `--local-control` のみ。bootstrap は環境変数・ファイル・ログに保存せず、Worker の stdin とも共有しない。Gateway は常駐コアへ接続して片方の値を提示し、常駐コアはその同一接続上で他方を付けて照会する。再起動で接続・ポート・認証情報を作り直す。接続先を起動パイプに束縛し、認証済み接続以外には要求・一覧を送らない。同一ユーザーのプロセスメモリ参照に対する防御や暗号化 transport は提供しない。

bootstrap/照会は3秒上限。Gateway の要求は改行込み4096バイト、応答は64 KiB。常駐コア側の Gateway 認証は1接続ずつ100ms上限で処理し、照会全体の期限でも打ち切る。無制限のタスクやアプリ内接続キューは生成しない。既存 CLI 側の32並行 reader・32要求キュー・4095バイトの要求制限を維持する。認証済み管理操作は直列のため、照会待ちの最大3秒は他の操作や監視を遅らせる。

大量一覧のページ化は未実装。上限超過は取得失敗とし、切り詰めた一覧を完全な一覧として返さない。CLI の JSON ラップ後の64 KiB制限でも取得失敗になり得る。
